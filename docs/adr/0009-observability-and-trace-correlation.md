# ADR-0009: Observability (OpenTelemetry, Langfuse, correlation with client traces)

- Status: Accepted (architecture phase)
- Date: 2026-11-08
- Spec refs: §2.3 G, §2.4, §3.4, §6 ("OpenTelemetry traces available", "Shared request IDs enable end-to-end tracing", "Application quality results can be associated with inference executions"), §8 item 8

## Context

The spec requires every request to have a traceable lifecycle (request → policy → router → cache → provider → normalisation → accounting → response), with no indiscriminate logging of prompts or keys. Mezvuat plans to use Langfuse for application-level LLM tracing, and its evaluation results must be linkable to ModelMesh executions.

Constraints on this machine: the 4 GB Docker VM cap. Self-hosted Langfuse (v3 and v4) needs Postgres + ClickHouse (at least 25.12, about 8 GiB recommended) + Redis + S3/MinIO, which does not fit (ENVIRONMENT.md).

## Options considered

| Concern | Options | Choice |
|---|---|---|
| Instrumentation | OTel SDK; vendor SDKs; Langfuse SDK | **OTel SDK** (spec standard) with OTLP/HTTP export |
| Trace backend (local) | Jaeger v2 (`jaegertracing/jaeger:2.x`; the old `all-in-one` v1 is EOL); `grafana/otel-lgtm` (traces, metrics, logs, Grafana); collector + Tempo | **Jaeger v2**, because it is light. `grafana/otel-lgtm` was rejected: Grafana, Loki, Tempo and Mimir are AGPL, which DECISIONS D5 excludes |
| Langfuse in ModelMesh | adopt; skip; optional OTLP export | **Not adopted in v1.** It overlaps with OTel for an infrastructure product and can't be self-hosted here. ModelMesh emits OTel GenAI semantic-convention attributes, which Langfuse can ingest over OTLP if an operator points an exporter at it. That is a config change, not a dependency |
| Correlation key | trace id only; request ids only; both | **Both, plus an application-level correlation id** |

## Decision

### Traces

- Server span `POST /v1/chat/completions` (from the FastAPI instrumentation). Child spans: `mm.auth`, `mm.policy`, `mm.cache.lookup`, `mm.route`, `mm.attempt` (one per attempt, containing the httpx client span to the provider), `mm.validate`, `mm.accounting`.
- Attributes follow the OTel **GenAI semantic conventions**, which are still in development status:
  - `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`
  - `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.finish_reasons`
  - plus `mm.*`: `request_id`, `tenant_id`, `task_type`, `routing.mode`, `routing.policy`, `cache.status`, `attempt.outcome`, `fallback_used`, `cost.estimated_usd`
- **No prompt or response content and no secrets** in spans or logs. The GenAI content-capture option stays off. `end_user_id` is recorded only as the caller-supplied hash. The provider URL is recorded without query strings.
- The API-key value never appears anywhere. The key id (`key_…`) and its 8-character prefix may appear.
- **W3C Trace Context:** an incoming `traceparent`/`tracestate` is continued (parent-based sampler), so a Mezvuat span becomes the parent of ModelMesh's server span. `tracestate` is passed through unchanged. Baggage is not propagated to providers, and outgoing `traceparent` to providers is disabled by default, because it would leak trace ids to third parties.
- Sampling: 100% in dev. In prod, parent-based with a ratio set by config. Error requests are always recorded in Postgres, whatever the trace sampling.

### Metrics

OTel metrics, exported through OTLP to any operator-configured backend (none is bundled; the usage dashboard reads Postgres):

- `mm.requests` (counter, by status, provider, model, task_type, cache status)
- `mm.request.duration`, `mm.attempt.duration`, `mm.ttft` (histograms)
- `mm.tokens` (by direction and source)
- `mm.cost.estimated_usd`
- `mm.fallbacks`
- `mm.breaker.state` (gauge)
- `mm.quota.remaining`
- `mm.router.decision_latency`
- `mm.cache.hits`

### Logs

- JSON lines through stdlib logging, with `trace_id`, `span_id` and `request_id` injected from context. One structured "request completed" log per request.
- **A redaction filter** drops known secret patterns and any `messages`/`content` fields. A unit test proves that a request containing a canary secret string never appears in captured logs or spans.

### Correlation contract with clients

Spec §6 combined criteria.

1. `X-Request-ID`: generated by the client, echoed, and stored as `client_request_id`.
2. `X-ModelMesh-Request-ID` (`mmr_<ULID>`): the primary key for `/v1/requests/{id}` and `/v1/feedback`.
3. **`modelmesh.trace_id`**: the 32-hex W3C trace id. This is an **additive response field**, so a client can join its own trace records (Langfuse or other) to ModelMesh traces even when they live in different backends.
4. `metadata.correlation_id`: the client's run-level id (for example a Mezvuat research run). **Additive endpoint `GET /v1/requests?correlation_id=…`** lists that run's executions, which supports the combined benchmark report.

Mezvuat stores (1)–(4) with its evaluation records and posts quality labels to `/v1/feedback` keyed by the `mmr_` id. ModelMesh joins labels to executions. Neither system reads the other's database.

## Consequences

- Traces from both products share trace ids but may sit in different backends (Mezvuat in Langfuse, ModelMesh in Jaeger). Correlation works through ids, not a shared UI. A unified view needs both exporting to one OTLP backend, which is optional and a deployment choice.
- No Langfuse dependency or container in ModelMesh.

## Verification plan

- Unit test with the in-memory span exporter: a full request produces the expected span tree, attributes, and **no content attributes**. An incoming `traceparent` becomes the parent, and `modelmesh.trace_id` equals the span's trace id.
- Log/span redaction canary test.
- Integration test (M1): compose with Jaeger, issue a request, and query the Jaeger API for the trace by id.
- Combined test (M8, with Mezvuat): one trace id spans a Mezvuat run and ModelMesh, and `/v1/requests?correlation_id=` returns all its executions.

## Amendment 2026-11-09 (implementation)

- The attempt span is created by hand (`mm.attempt`) rather than with the httpx instrumentation. That also guarantees no `traceparent` is sent to providers.
- `mm.breaker.state` and `mm.quota.remaining` are not exported yet. `/v1/providers` and `/v1/models` report the same information.
