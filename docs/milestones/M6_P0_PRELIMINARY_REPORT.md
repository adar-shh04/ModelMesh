> **Preliminary.** Built from the P0 pilot (`pilot-2026-11-11`), not from P1. The test sets hold 32 (held-out queries) and 80 (leave-one-dataset-out) prompts, four models and only automatically labelled task types. Decisions:

- **Pool: gemini/gemini-3.1-flash-lite, groq/openai/gpt-oss-120b, ollama/llama3.2:3b, ollama/qwen3:4b.** These four are the models with an observation on every auto-labelled item they are evaluated on. gpt-oss-20b (95 of 180 auto-labelled items), gemini-3.6-flash and both OpenRouter models (the 40 `query_classification` items only) are left out of routing and reported separately below. A router choosing among models it has no labels for cannot be evaluated without imputing labels, which this report never does.
- **Items: complete cells only.** An item is used only when all pool models have a recorded outcome for it. That leaves 160 items in the primary analysis (`jsonschemabench` drops out: gpt-oss-120b never reached it).
- **Labels: automatic only.** `query_rewriting`, `research_planning` and `final_response` need the judge pipeline, which has not run, so they carry no label and are excluded. `evidence_synthesis` needs token F1 ≥ 0.5 **and** judge faithfulness ≥ 4 under ADR-0005; the judge half is missing, so the primary analysis excludes it and a sensitivity variant adds it with the F1 half alone (an optimistic label).
- **Failures count as not accepted** (502 all attempts failed, 504 deadline, schema failure): the client got no acceptable answer from that call. A variant that drops failed cells instead is reported. Failed cells have no recorded cost; they are charged the median successful cost of that model and task type. That is the only imputed quantity, and it is a cost, not a label.
- B0b's lookup uses train plus validation acceptance (ADR-0004 says validation). P0 validation has 4 to 12 items per task type, and giving B0b the same data the learned router sees makes the comparison stricter. The validation-only lookup is reported alongside.
- Costs are the gateway's estimated list-price cost (actual spend was $0 on free tiers). Both Ollama models cost $0, so Cheapest-Single is the better of the two on selection data.

## Splits

- Held-out queries: grouped 60/20/20 within each (task type, source): train 96, validation 32, test 32. Groups join items from one source question and prompts with embedding cosine above 0.95. Asserted: 0 groups cross splits; the highest train/validation/test cross-split cosine is 0.9490.
- The split manifest (item ids, content hashes, split) is committed as `data/manifests/p0_router_split.json`. It is P0-only.
- Workload shift (a), leave-one-dataset-out: query_classification/banking77, query_classification/clinc150, citation_verification/scifact, citation_verification/attributionbench. Each fold refits the selected configuration on the remaining items (75/25 train/validation, grouped) and predicts the held-out source. The folds are pooled. Hyper-parameters are not re-selected.
- Workload shift (b), mixture shift: the held-out test set re-weighted to fixed task-type shares (Mezvuat-like: verification and assessment heavy; chat-like: general heavy). Shares were fixed in code before results were computed.
- The test set was evaluated by the same code twice: one smoke run with 20 resamples to catch crashes, then the reported run. Between them, only the overhead breakdown and a numerically equivalent isotonic implementation changed; no modelling or selection choice changed after the smoke run.

## Caveats

These notes are hand-written and appended to the generated report. They contain no new measurements.

- **Sample size.** The held-out-query test set is 32 prompts and the leave-one-dataset-out set is 80. ADR-0005 planned about 240 test prompts for P1. Every interval above is wide, and the per-task calibration rows rest on 16–48 cells.
- **Coverage is in run order, not random.** Which items each model reached depends on when its quota ran out. The four-model pool and the complete-cell restriction avoid imputation, but the items that survive are not a random sample of the pilot: `jsonschemabench`, the judge task types and every item gpt-oss-120b never reached are absent.
- **Failures as rejects mix reliability into quality.** Most failed cells are gemini-3.1-flash-lite's 502s (upstream, not item-dependent) and qwen3:4b's schema failures and timeouts (model-dependent). The failures-dropped variant shows how much this choice matters: B0b and the learned routers change rank between the two variants.
- **Calibration.** Per-task isotonic tables fitted on 4–12 validation items made ECE worse than the raw scores for most families and task types. No family meets the 0.05 promotion gate on P0. P1 needs at least 30 calibration points per task type (the ADR's own threshold for `calibrated: true`), or cross-fitted calibration.
- **Embedding latency.** The 10 ms budget without embedding is met by a wide margin, and the 25 ms budget with embedding is missed by a wide margin. The gateway embeds with fastembed on one thread (`threads=1`), and the router embeds the system prompt plus the final user message, which for citation and evidence prompts reaches the model's 512-token limit. The semantic-cache measurement in M4 (13.8 ms p95) used short texts. The machine was also running the evaluation itself while it measured. Options for P1, none tried here: embed a shorter text (needs retraining), give the embedder more threads, or reuse the semantic cache's embedding when both run on the same text.
- **Online versus offline cost and latency.** Offline routing uses the artifact's fitted token estimate, per-(model, task) output-token medians and latency model. The online Estimator still uses its own token estimate and the static `PREDICTED_OUTPUT_TOKENS` table; the artifact supplies only quality. A shadow decision can therefore differ from the offline replay of the same request on cost ties. Wiring the artifact's predictors into the Estimator is P1 work.
- **Conventions that shape AIQ.** Each router's hull includes the Cheapest-Single point and is flat to the right of its last vertex; the cost range runs from Cheapest-Single to the most expensive single model on the same items. Both Ollama models cost $0, so the left end of every curve is a free model. "Random" is the expected outcome of a uniform choice, not a sampled one.
- **Leave-one-dataset-out references.** Each fold's routers use only that fold's training data, but the pooled AIQ range and the Best-Single reference come from the main split's selection data, which includes some of the held-out sources' items. This affects the yardstick, not the routers.
- **Robustness** covers typos only, on the 32 test prompts. Paraphrases need an LLM, and this milestone made no provider calls.
- **The test set was touched twice** by identical evaluation code (a 20-resample smoke run, then the reported run). This is recorded above; nothing was tuned on it.
